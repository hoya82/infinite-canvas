# Infinite Canvas — 스포이드(컬러 피커) 툴

작성일: 2026-08-14
상태: 구현 완료, 자동 검증 + 브라우저 수동(Playwright/CDP) 검증 완료

## 요구사항

1. 스포이드 툴을 추가하고 툴바에도 노출한다.
2. 단축키는 Ctrl+클릭이다. Ctrl을 누르고 있는 동안 툴바의 스포이드가 (일시적으로) 활성 표시되고,
   그 상태에서 클릭하면 클릭 좌표의 색을 뽑아 전경색으로 삼는다.
3. 뽑는 색은 **활성 레이어의 원본 픽셀**이어야 한다 — 여러 레이어를 블렌드한 합성(컴포지팅) 결과가
   아니다. 예: 위 레이어가 불투명하게 덮고 있어 화면에는 다른 색이 보이더라도, 활성 레이어가 아래
   레이어라면 아래 레이어의 색을 뽑아야 한다.

## 구현 내용

- **`input.ts`** — 기존에 Space/Ctrl 조합으로 `pan`/`zoom`/`draw`를 파생시키던 `baseMode$`에
  `eyedropper`를 추가했다. Space는 "어느 클러스터인가"(pan-계열 vs draw-계열), Ctrl은 "그 안의 보조
  동작"(zoom vs eyedropper)을 결정하는 구조로 재해석해, `!space && ctrl` 조합을 `eyedropper`로
  매핑했다. `cursorMode$`도 같은 방식으로 `eyedropper` 커서 모드를 추가했다. Space+Ctrl(zoom)과
  Ctrl 단독(eyedropper)이 서로 다른 브랜치라 기존 줌 동작과 충돌하지 않는다.
- **`eyedropper.ts`(신규)** — 픽업 로직을 담당하는 순수 함수 + RxJS 스트림.
  - `worldToTilePixel(worldX, worldY)`: 월드 좌표를 타일 좌표 + 그 타일 캔버스 내부의 로컬 픽셀
    좌표로 변환하는 순수 함수. 음수 좌표, 타일 경계, 소수점 좌표를 모두 올바르게 처리하도록
    `eyedropper.spec.ts`로 단위 테스트했다(4케이스).
  - `sampleLayerColor(tileStore, layerId, worldX, worldY)`: `TileStore`가 이미 레이어별로 분리해
    들고 있는 `layerCanvases`(`brushEngine.ts`의 `drawStamp`가 스탬프를 찍을 때 쓰는 것과 동일한
    구조) 중 **activeLayerId 하나만** 골라 `getImageData`로 픽셀을 읽는다. 렌더러가 매 프레임
    수행하는 레이어 블렌드(컴포지팅)와는 완전히 별개 경로라 요구사항 3이 구조적으로 보장된다.
    완전 투명(alpha=0) 픽셀이거나 타일이 아직 로드되지 않았으면 `null`을 반환해 전경색을 바꾸지
    않는다.
  - `createEyedropperPick$`: `input.pointerDown$`을 `input.baseMode$`와 결합해, `mode ===
    'eyedropper'`(Ctrl 홀드 중)이거나 `mode === 'draw' && tool === 'eyedropper'`(스포이드가 선택된
    도구)일 때만 픽업을 실행한다. `brushEngine.ts`의 `createStroke$`와 동일한 스타일(호출부가
    subscribe/unsubscribe로 생명주기 관리)로 맞췄다.
- **`brushEngine.ts`** — `createStroke$`의 `exhaustMap` 안에서 `settings.tool === 'eyedropper'`이면
  `canvas.setPointerCapture`도 하지 않고 즉시 `EMPTY`를 반환하도록 가드를 추가했다. 스포이드가
  "선택된 도구"인 상태에서 Ctrl 없이 클릭해도(baseMode가 `draw`로 유지되므로) 붓/지우개 스탬프가
  찍히지 않게 막는 역할 — Ctrl 홀드로 진입하는 momentary `eyedropper` 모드는 애초에 baseMode가
  `draw`가 아니라 이 가드 없이도 `createStroke$`가 반응하지 않는다.
- **`toolState.svelte.ts`** — `Tool`에 `'eyedropper'`를 추가했고(`types.ts`), `eyedropperKeyHeld:
  boolean` 상태를 새로 뒀다. `CanvasStage`가 `input.baseMode$`를 구독해 이 값을 갱신하고,
  `Toolbar`가 이 값을 읽어 (Ctrl을 누르고 있을 때) 스포이드 버튼을 momentary로 강조 표시한다 —
  두 컴포넌트가 형제라 이 싱글톤을 통하지 않고는 상태를 주고받을 방법이 없다.
- **`CanvasStage.svelte`**:
  - `createEyedropperPick$`을 구독해 `onPick`에서 `toolState.color = hex`만 한다(히스토리에는
    안 쌓는다 — 아래 "설계 결정" 참고).
  - `input.cursorMode$`가 주는 `cursorMode`(Ctrl 홀드 여부만 반영)와 `toolState.tool`을 합쳐
    `effectiveCursorMode`를 파생시켰다: Ctrl을 안 눌렀어도 스포이드가 "선택된 도구"면 같은
    `eyedropper` 커서를 보여줘야 하기 때문. 캔버스 CSS 커서는 `crosshair`, 브러시 크기를 보여주는
    원형 커서 오버레이(`.brush-cursor`)는 `effectiveCursorMode === 'draw'`일 때만 표시해 스포이드
    선택 중엔 숨긴다.
- **`Toolbar.svelte`** — 펜/지우개 버튼 옆에 스포이드 버튼(`lucide-svelte/icons/pipette`)을
  추가했다. `active` 클래스는 `toolState.tool === 'eyedropper' || toolState.eyedropperKeyHeld` —
  영구 선택 상태와 momentary Ctrl 홀드 상태 둘 다 반영한다. 스포이드가 선택된 동안엔 "크기"가 의미
  없으므로 붓/지우개 크기 슬라이더를 숨겼다.

### 설계 결정

- **툴바 버튼 = 영구 선택, Ctrl+Click = momentary override.** Krita/Photoshop 관례를 그대로
  따랐다 — 툴바에서 스포이드를 클릭하면 그 도구가 선택된 채로 남아 이후 클릭마다(Ctrl 없이도)
  픽업하고, 반대로 붓/지우개가 선택된 상태에서 Ctrl을 누르고 있는 동안만 일시적으로 스포이드로
  바뀌었다가 떼면 원래 도구로 자동 복귀한다. 후자는 `toolState.tool`을 전혀 건드리지 않기 때문에
  "복귀"를 위한 별도 로직이 필요 없다.
- **픽업은 컬러 히스토리에 안 쌓는다.** 컬러 피커 문서(`2026-08-14 Color picker.md`)에서 정한
  규칙 — "실제로 그 색을 써서 그렸을 때만 히스토리에 쌓인다" — 을 그대로 따랐다. 스포이드로 뽑는
  행위는 "그리기"가 아니라 "읽기"이므로 히스토리 갱신 대상이 아니라고 판단했다.
- **완전 투명 픽셀은 무시한다.** 이 앱의 전경색은 alpha 없는 6자리 hex 하나뿐이라, 투명한 지점을
  뽑았을 때 표현할 수 있는 의미 있는 색이 없다 — 조용히 무시하고 전경색을 그대로 둔다.

## 검증

- **단위 테스트**: `eyedropper.spec.ts` 신규 4개(`worldToTilePixel`의 타일 경계/음수 좌표/소수점
  처리) — 전체 스위트 16개 파일 71개 테스트 전부 통과. `svelte-check` 0 에러, `svelte-autofixer`
  MCP로 두 컴포넌트(`CanvasStage.svelte`, `Toolbar.svelte`) 모두 문법/구조 이슈 없음 확인,
  lint(prettier+eslint) 통과.
- **브라우저 검증**(WSL→Windows Chrome, CDP 연결, dev 서버는 사용자가 이미 실행 중이던
  `localhost:5173` 그대로 사용, Playwright로 자동화): 16개 어서션 전부 통과.
  - Ctrl을 누르고 있는 동안 툴바 스포이드 버튼이 강조되고 캔버스 커서가 `crosshair`로 바뀜, Ctrl을
    떼면 즉시 원래(brush) 상태로 복귀함을 확인.
  - Ctrl+Click으로 미리 빨간 점을 그려둔 좌표를 찍으면 전경색이 정확히 그 빨강(`rgb(255, 0, 0)`)
    으로 바뀌고, 그 클릭이 실제로는 아무것도 그리지 않았음(픽셀이 여전히 빨강 그대로)을
    `getImageData`로 확인. 픽업 후에도 활성 도구는 여전히 brush임(momentary였음)을 확인.
  - 스포이드로 뽑은 색은 컬러 히스토리에 쌓이지 않음(2→2, 변화 없음)을 확인 — 직전에 브러시로 그린
    두 색은 정상적으로 히스토리에 쌓인 것과 대비.
  - 스포이드를 툴바에서 클릭해 영구 선택한 뒤에는 Ctrl 없이 클릭만으로도 픽업됨, 크기 슬라이더가
    숨겨짐, 빈(완전 투명) 좌표를 클릭해도 캔버스가 전혀 변하지 않음(그려지지 않음)을 확인.
  - **핵심 요구사항(합성 결과가 아닌 활성 레이어)**: Layer1의 (200,200)에 빨강을 그린 뒤, 새
    Layer2를 그 위에 만들어 같은 좌표를 불투명 노란색으로 완전히 덮었다. 이 시점에 화면에 실제로
    렌더링되는(컴포지팅된) 픽셀이 노란색(`rgb(255, 255, 0)`)임을 먼저 확인했다. 그다음 활성
    레이어를 다시 Layer1(빨강)로 돌려놓고 같은 좌표를 스포이드로 찍었더니 — 화면엔 여전히 노란색이
    보이는 상태임에도 — 전경색이 Layer1의 빨강(`rgb(255, 0, 0)`)으로 바뀜을 확인해, 합성 결과가
    아니라 활성 레이어 원본을 읽는다는 요구사항을 직접 검증했다.

## 후속 수정 — 캔버스 커서를 스포이드 SVG 아이콘으로 교체

1차 구현은 캔버스 위 스포이드 커서를 순정 CSS `crosshair` 키워드로 처리했는데, 사용자가 요청했다:
스포이드 SVG 아이콘을 커서로 쓰고, 그 아이콘의 끝부분(왼쪽 하단, 실제로 잉크가 닿는 지점)이 뽑힐
픽셀 좌표와 정확히 맞아떨어져야 한다(hotspot 정렬).

- **`eyedropperCursor.ts`(신규)** — 툴바 버튼과 같은 lucide `pipette` 아이콘의 path를 그대로
  재사용해 커서용 SVG 문자열을 만든다. 원본 24x24 뷰박스에서 "잉크가 떨어지는" 지점은 왼쪽 아래의
  짧은 선분(`m2 22 .414-.414`)이 시작하는 `(2, 22)`다. 배경이 어떤 색이든 항상 보이도록 굵은 흰
  stroke(halo)를 먼저 깔고 그 위에 검은 stroke를 덧그리는 이중 테두리 기법을 썼다(Toolbar
  스워치/ColorPicker 미리보기와 같은 방식). halo가 뷰박스 경계에서 잘리지 않도록 뷰박스에 `-2`
  여백(`viewBox="-2 -2 28 28"`, `width/height=28`)을 추가했고, 그만큼 hotspot도 원본 `(2,22)`에서
  `(4,24)`로 함께 옮겨 실제 클릭 좌표와 시각적 팁이 정확히 일치하게 했다. 최종 값은
  `url("data:image/svg+xml,...") 4 24, crosshair`(SVG 커서 로드 실패 시 crosshair 폴백) 형태의
  완성된 CSS `cursor` 값 문자열(`EYEDROPPER_CURSOR`)로 내보낸다.
- **`CanvasStage.svelte`** — `canvasCursorStyle`의 `eyedropper` 분기를 `'crosshair'` 리터럴에서
  `EYEDROPPER_CURSOR`로 교체했다. Ctrl 홀드(momentary)든 스포이드가 선택된 도구(영구)든 이미
  `effectiveCursorMode === 'eyedropper'` 하나로 합쳐져 있어 이 교체만으로 두 경로 모두 커버된다.

### 검증

- 실제 앱에서 `getComputedStyle(canvas).cursor`로 적용된 값을 읽어 `url("data:image/svg+xml,...")
  4 24, crosshair` 형태임을 확인했고, 그 data URI를 디코드한 SVG를 저장해 좌표 계산을 재검증했다:
  뷰박스가 `-2 -2 28 28`이므로 원본 팁 좌표 `(2,22)`에 뷰박스 오프셋 `(+2,+2)`를 더한 `(4,24)`가
  hotspot과 정확히 일치함을 확인.
- **알려진 검증 한계**: Chrome DevTools Protocol(`Page.captureScreenshot`, Playwright의
  `page.screenshot()`이 내부적으로 사용)은 OS/브라우저가 합성하는 마우스 커서를 스크린샷에 포함하지
  않는다 — 커스텀 SVG 커서든 순정 커서든 마찬가지로, 이는 자동화 도구의 근본적인 한계라 이 세션에서
  우회할 방법이 없었다(실제로 캔버스 위에 마우스를 올리고 스크린샷을 찍어봤더니 커서 없이 캔버스만
  찍히는 것으로 직접 확인). 그래서 커서의 실제 시각적 정렬은 hotspot 좌표 계산(위 검증)으로
  간접적으로만 확인했고, 최종 시각 확인을 위해 세션 종료 시점에 사용자의 실제 Chrome 창에서 스포이드
  도구를 활성화하고 캔버스 위로 마우스를 옮겨둔 상태로 남겨, 사용자가 직접 눈으로 확인할 수 있게
  했다.

## 알려진 한계 (의도적으로 남겨둠)

- 픽업은 pointerdown 시점 한 번만 일어난다(드래그하며 색이 계속 바뀌는 라이브 프리뷰는 없음). 요구
  범위가 "클릭 시 추출"이라 이 이상의 드래그 프리뷰는 스코프 밖으로 판단했다.
- E 키(브러시/지우개 토글)는 기존 그대로 브러시/지우개 사이만 오간다. 스포이드가 선택된 상태에서
  E를 누르면 지우개로 바뀐다(`toggleTool()`의 기존 삼항식이 "eraser가 아니면 eraser로" 동작하는
  기존 로직을 그대로 둔 결과) — 별도 요청이 없어 손대지 않았다.
