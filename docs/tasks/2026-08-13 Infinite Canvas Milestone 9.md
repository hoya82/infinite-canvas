# Infinite Canvas — Milestone 9 (브라우저 데모 피드백 반영)

작성일: 2026-08-13
상태: 적용 완료(1차 3건 + 사용자 정정 뒤 2차 수정 2건), 스크린샷·실측 커서 값으로 전부 육안/코드 확인

## 개요

M1~M8을 자동화된 Playwright 스크립트로 실제 Windows Chrome(사용자가 실행한 `localhost:5173` dev 서버, WSL→CDP 연결)에서 사람 손 속도에 맞춰 시연했다(스트로크 보간 이동, 컬러 피커 조작, 지우개 토글, 패닝/줌, 레이어 추가+Multiply, 도큐먼트 전환, 저장+새로고침까지 전 과정). 사용자가 그 화면을 직접 보고 세 가지 UI 문제를 지적했다. 이 문서는 그 문제들과 적용할 수정 방법을 정리한다.

## 문제 1 — 컬러 피커 스워치가 안 보인다 (특히 검은색일 때)

**증상**: 툴바 오른쪽 끝의 전경색 스워치가 어두운 툴바 배경(`#232323`/`#3a3a3a`) 위에서 테두리 없이 배경색만 칠해져 있어, 선택한 색이 어두운 색(특히 검정 `#1a1a1a`, 기본값)이면 스워치 자체가 거의 안 보인다. `ColorPicker.svelte`의 hex 미리보기 박스(`.preview`)도 `border: 1px solid #555` 하나뿐이라 같은 문제가 있다. 또한 피커 팝오버가 스워치 바로 아래(오른쪽 끝, 레이어 패널과 겹치는 위치)에 뜬다.

**적용할 수정**:

- 스워치를 중첩 박스 구조로 바꾼다: 바깥쪽 **흰색 굵은 테두리**(패딩+흰 배경으로 구현) → 그 안쪽에 **검은 얇은 선**(1px 실선 border) → 그 안쪽에 실제 선택 색상 채우기. 흰 테두리는 어두운 배경에서, 검은 선은 흰색/밝은 선택색에서 각각 대비를 보장하므로 어떤 색을 선택해도 스워치 경계가 항상 보인다. `ColorPicker.svelte`의 hex 미리보기 박스에도 동일한 구조를 적용한다.
- 피커 팝오버 위치를 스워치 기준 상대 배치(`position: absolute; right: 0`)에서 **Top panel(툴바) 중앙에 고정 배치**(`position: fixed; left: 50%; transform: translateX(-50%)`)로 바꾼다.

> **1차 적용 후 사용자 정정**: "옮겨달라고 한 건 팝업이 아니라 컬러 피커 **아이콘**이다. 팝업은 아이콘에 anchor한다." — 1차 적용에서는 아이콘은 그대로 오른쪽 끝에 두고 팝업만 뷰포트 기준 `position: fixed`로 중앙에 고정했는데, 이는 요구사항을 반대로 구현한 것이었다. 2차로 `Toolbar.svelte`를 좌/중앙/우 3분할 flex 레이아웃(`left-group`/`center-group`/`right-group`, 양쪽에 `flex:1`을 줘서 가운데가 자연히 중앙에 오게 함)으로 바꿔 **스워치 아이콘 자체를 중앙에 배치**했고, 팝업은 다시 `position: absolute`로 스워치를 기준으로 그 바로 아래 anchor되도록 되돌렸다(아이콘이 어디로 옮겨지든 팝업이 항상 따라간다).

## 문제 2 — 레이어 패널에 불필요한 가로 스크롤바

**증상**: 레이어 패널(고정 폭 260px) 안의 각 레이어 행에서 Normal/Multiply `<select>`가 내용물(문자열) 기준 최소 너비를 강제해 행 전체가 패널 폭을 넘어서고, `ul`에 `overflow-y: auto`만 지정하고 `overflow-x`를 지정하지 않으면 CSS 스펙상 "한쪽 축만 auto/scroll이고 다른 쪽이 visible이면 안 되므로 다른 쪽도 auto로 강제 승격"되는 규칙 때문에 `overflow-x`가 암묵적으로 `auto`가 되어(https://developer.mozilla.org/ko/docs/Web/CSS/overflow-x 관련 스펙 동작) 가로 스크롤바가 나타난다.

**적용할 수정**:

- `.row select`에 `min-width: 0`을 줘서 flex item이 내용물 너비 아래로도 줄어들 수 있게 하고, 폭을 줄인다(폰트도 살짝 축소).
- `ul`(레이어 목록)에 `overflow-x: hidden`을 명시해 암묵적 승격을 원천 차단한다.

## 문제 3 — 타일 경계에 1px 흰 선이 보인다

**증상**: 인접한 두 타일을 각각 별도의 `drawImage` 호출로 그리는데, 화면 좌표(`screenX`, `size`)가 부동소수점이라 각 `drawImage` 호출이 브라우저의 래스터라이저에서 독립적으로 정수 디바이스 픽셀에 반올림되면서, 두 타일의 경계가 수학적으로는 정확히 맞닿아도 각자 다르게 반올림되어 그 사이에 1px 틈이 생길 수 있다. 그 틈으로 타일보다 먼저 전체 화면에 그려둔 배경(기본 흰색)이 비쳐 보이는 것이 원인이다.

**적용할 수정**: 타일 렌더링에서 흔히 쓰는 표준적인 방법대로, 각 타일을 실제 크기보다 아주 살짝(1 논리 픽셀) 더 크게 그려서 인접 타일끼리 미세하게 겹치게 한다(`dx - 0.5, dy - 0.5, size + 1, size + 1`). 내용물이 살짝(서브픽셀 단위) 확대되는 대가가 있지만 육안으로는 구별되지 않고, 배경이 비치는 흰 선은 사라진다.

## 추가 요구사항 — 패닝/줌 중 커서 아이콘 전환 (RxJS)

1차 수정을 확인하는 과정에서 사용자가 새로 요청했다: **Space+드래그로 패닝하는 동안 커서가 손(grab) 모양으로 바뀌고, 놓으면 원래 도구 커서로 돌아와야 한다**. 이 press–drag–release 생명주기를 RxJS로 명시적으로 구성할 것. **Ctrl+Space가 눌려 있는 동안은(드래그 여부와 무관하게) 돋보기(zoom) 모양을 유지**하고, **마우스 휠로 줌할 때는 커서를 바꾸지 않는다**(휠은 순간적인 조작이라 커서 상태와 무관해야 함).

**적용한 방법**: `input.ts`에 `CursorMode = 'draw' | 'grab' | 'grabbing' | 'zoom'`과 `cursorMode$` 옵저버블을 추가했다.

- 이미 있던 `baseMode$`(Space/Ctrl의 keydown/keyup을 곧바로 반영하는 옵저버블 — 그 자체가 이미 "press ~ release" 생명주기다)에, **실제로 드래그 중인지**를 나타내는 `panDragActive$`(pan 모드에서의 pointerdown → true, pointerup/cancel → false)를 `combineLatest`로 합쳤다.
- `mode === 'zoom'`이면 무조건 `'zoom'`, `mode === 'pan'`이면 드래그 중 여부에 따라 `'grabbing'`/`'grab'`, 그 외(`'draw'`)는 원래 도구로 매핑한다.
- 마우스 휠 줌(`wheelZoom$`)은 이 파생 체인에 전혀 관여하지 않으므로 휠을 굴려도 커서가 그대로 유지된다 — 별도 예외 처리를 추가한 게 아니라 애초에 관련이 없어서 자연스럽게 요구사항을 만족한다.
- `CanvasStage.svelte`가 `cursorMode$`를 구독해 캔버스의 CSS `cursor`를 그대로 세팅한다(`grab`/`grabbing`/`zoom-in`은 브라우저 네이티브 커서 키워드라 별도 아이콘 에셋이 필요 없다). `draw` 모드일 때만 기존 브러시 크기 원 오버레이를 보여준다.

## 적용 결과

전부 계획대로 구현했다(`Toolbar.svelte`, `ColorPicker.svelte`, `LayerPanel.svelte`, `renderer.ts`, `input.ts`, `CanvasStage.svelte`). 두 라운드 모두 `bun run check`/`lint`/전체 테스트 49개/빌드가 그대로 통과했다 — 스타일·렌더링·입력 파생 로직 조정이라 기존 테스트에 영향이 없었다.

같은 WSL→Chrome CDP 세션에서 dev 서버 페이지를 새로고침해 다시 스크린샷/실측으로 확인했다:

- **문제 1(정정 반영 후)**: 스워치 아이콘이 툴바 중앙에 위치하고, 팝업이 그 아이콘 바로 아래에 anchor되어 뜸을 스크린샷으로 확인. 전경색이 기본값(검정 `#1a1a1a`)이어도 흰 테두리+검은 안쪽 박스로 스워치와 hex 미리보기 둘 다 명확히 보임을 확인.
- **문제 2**: `document.querySelector('.layer-panel ul').scrollWidth`와 `clientWidth`를 직접 측정해 `260 === 260`(오버플로 없음)을 확인했고, 레이어 2장(Normal/Multiply)이 있는 상태를 크롭 스크린샷으로도 가로 스크롤바 없이 "Multiply"와 "100%"가 잘리지 않고 표시됨을 확인.
- **문제 3**: 타일 경계(월드 x=512)를 가로지르는 두꺼운(150px) 스트로크를 그린 뒤 그 지점을 마우스 휠로 16번(약 4배) 확대해 스크린샷을 찍었다. 이 정도로 확대하면 원래 버그가 있었다면 이음매 틈이 여러 픽셀 폭으로 크게 보였을 텐데, 경계 부근 300×300 클로즈업에서 흰 선이나 끊김 없이 하나로 이어진 칠 영역만 보임을 확인했다.
- **커서 전환**: `getComputedStyle(canvas).cursor`를 각 단계마다 직접 읽어 전부 기대한 값과 일치함을 확인했다 — draw 상태 `none`(커스텀 브러시 원이 대신 보임) → Space만 누름 `grab` → Space+드래그 중 `grabbing` → 마우스를 떼도 Space를 유지하면 다시 `grab` → Space를 떼면 `none`(원래 도구) → Ctrl+Space `zoom-in` → 그 상태에서 키를 떼고 마우스 휠만 굴리면 `none`을 그대로 유지(휠은 커서에 영향 없음). press–drag–release 전 구간이 정확히 요구한 대로 동작한다.

검증에 쓴 임시 Playwright 스크립트는 저장소에 커밋하지 않는 1회성 검증용이라 확인 후마다 삭제했다.
