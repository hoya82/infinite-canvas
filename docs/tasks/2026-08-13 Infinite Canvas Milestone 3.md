# Infinite Canvas — Milestone 3 (드로잉 엔진)

작성일: 2026-08-13
상태: 구현 완료(자동 검증 완료), 브라우저 수동 검증은 M2와 묶어서 별도로 진행

## 개요

[Milestone 2](2026-08-13%20Infinite%20Canvas%20Milestone%202.md)의 렌더링 파이프라인 위에 실제로 그리는 기능을 얹는다. 핵심은 사용자가 계획 단계에서 직접 지시한 두 가지다: **펜 스트로크 생명주기를 RxJS FSM으로 구현**하는 것과, **타일 경계를 넘는 스트로크가 이음매 없이 이어지는 것**.

## 구현 내용

- `toolState.svelte.ts` — 도구(펜/지우개) + 각각 독립된 크기(`brushSize`/`eraserSize`) + 전경색의 반응형 상태.
- `document.svelte.ts` — `activeLayerId` 추가(지금 그리기 대상 레이어). 도큐먼트를 열면 기본으로 스택 최상단 레이어를 활성화한다.
- `input.ts` 확장 — `pointerEnter$`/`pointerLeave$`(커서 오버레이 표시 여부), `toggleTool$`(`E` 키, 텍스트 입력 포커스 중에는 무시).
- `tileStore.ts`에 `getForDrawing` 추가 — 브러시가 타일을 **동기적으로** 확보하는 경로. 이미 메모리에 있으면 그대로 쓰고, 실제 존재하지만 아직 비동기 로드 중이면(경쟁조건 방지를 위해) 이번 스탬프는 건너뛰고 로드만 트리거하며, 완전히 새 타일(섬처럼 고립돼도 됨)이면 즉시 빈 캔버스로 만든다.
- `brushEngine.ts` — 이 마일스톤의 핵심.
  - **스트로크 FSM**: `pointerDown$`을 `baseMode$ === 'draw'`일 때만 통과시켜 `exhaustMap`으로 스트로크를 열고, `pointermove$ → getCoalescedEvents 펼침 → takeUntil(pointerup/cancel 또는 모드 이탈)`로 닫는다. `finalize()`에서 스트로크 커밋(dirty 마킹 + Dexie flush)을 한 곳에서 처리한다.
  - **스탬프 보간**: `scan`으로 "마지막 스탬프 위치"를 들고 있다가, 간격(spacing = 크기의 15%)을 넘어설 때만 그 사이를 균등 보간해 스탬프를 방출한다 — 이 보간은 스트로크 전체에 대해 월드 좌표 기준으로 한 번만 계산되고 타일마다 리셋되지 않는다.
  - **타일 경계 seamless 처리(사용자 추가 요구사항)**: 스탬프 하나마다 반경이 걸치는 모든 타일(코너 근처면 최대 4개)을 찾아, 정확히 512(TILE_SIZE)의 정수배 오프셋만 적용한 동일한 원(`arc`) 지오메트리를 각 타일에 그린다. 소수점 위치가 그대로 유지되므로 타일 경계를 넘어도 안티앨리어싱이 정확히 일치한다.
  - **필압**: `pointerType === 'pen'`일 때만 실제 `pressure` 값을 쓰고(반경 = 크기의 20%~100% 사이 보간), 마우스는 필압 센서가 없으므로 항상 최대 굵기로 취급한다(스펙상 마우스는 버튼이 눌린 동안 `pressure`가 0.5로 고정 보고되어 그대로 쓰면 굵기가 절반으로 고정되는 오류가 생기기 때문).
  - **지우개**: 같은 경로에 `globalCompositeOperation = 'destination-out'`만 다르게 적용.
  - **영속성 연결**: 스트로크 종료 시 터치된 타일마다 Dexie `tiles`(dirty=true, 새 타일이면 레코드 생성) + `tilePixels`(원본 픽셀) 갱신. 실제 lossless webp 재인코딩과 OPFS 저장은 M5의 역할이고, 여기서는 "언제든 조회 가능한 최신 작업 영역"까지만 책임진다.
- `CanvasStage.svelte` — 스트로크 스트림 구독, `E` 키 구독, 브러시 크기 커서 오버레이(포인터를 따라다니는 원 — 캔버스 위에서는 네이티브 커서를 숨기고 `mix-blend-mode: difference`로 배경과 상관없이 항상 보이게 함).

## 알려진 한계 (의도적으로 남겨둠)

`getForDrawing`은 "실제 존재하는 타일인데 아직 비동기 로드가 안 끝난" 아주 좁은 경쟁조건 구간에서 해당 스탬프 하나를 건너뛴다(다음 스탬프에서 재시도). 뷰포트에 들어오는 즉시 로드가 트리거되고 Dexie 조회는 보통 수 ms 안에 끝나므로 실제로 문제가 될 가능성은 낮지만, 완벽히 막으려면 스트로크 시작 시점에 로드를 기다리는 로직이 필요하다 — 이번 마일스톤에서는 과설계를 피하려고 넣지 않았다.

## 자체 리뷰로 잡은 버그

구현 중 두 가지를 스스로 발견해 고쳤다(둘 다 코드를 작성한 직후 svelte-autofixer/타입체크가 아니라 직접 재검토하며 발견):

1. **`StrokeControllerOptions`의 `tileStore`/`documentId`를 값으로 받으면 안 됨**: `createStroke$`는 캔버스가 마운트될 때 딱 한 번 호출되는데, `tileStore`/`documentId`를 일반 값으로 받아 그 자리에서 구조분해하면 그 순간의 스냅샷이 클로저에 박혀버린다. 나중에(M7) 도큐먼트를 전환해 `tileStore`가 새로 만들어져도 스트로크 핸들러는 여전히 옛 `tileStore`를 참조하게 되는 문제였다 — `getTileStore: () => TileStore | null` / `getDocumentId: () => string | null` 형태의 getter로 바꿔 스트로크가 시작되는 매 순간 최신 값을 다시 읽도록 고쳤다.
2. (테스트 작성 중 발견, 버그 아님으로 판명) `accumulateStamps`가 스탬프를 만들지 않을 때 `lastX/lastY`를 직전 포인터 위치가 아니라 마지막 "스탬프된" 위치로 유지하는 것이 처음엔 실수처럼 보였지만, 실제로는 의도된 동작이다 — 그렇지 않으면 느린 마우스 움직임(매 이벤트가 spacing보다 작게 움직이는 경우)에서 이동 거리가 누적되지 않아 스탬프가 영원히 안 찍히는 진짜 버그가 생긴다. 테스트로 이 사실을 명시적으로 남겼다.

## 검증

- `brushEngine.spec.ts`(순수 로직, Node 환경): 필압→반경 매핑(마우스 고정 굵기, 펜 비례, 최소값 클램프), 스탬프 보간(첫 포인트, 간격 미만 누적, 간격 초과 시 균등 보간, 타일 경계를 넘는 대각선 이동에서도 간격 유지) — 7개 전부 통과.
- 전체 스위트 23개(M1~M3 누적) 통과, `svelte-check` 0 에러, lint 통과, 빌드 성공.
- 브라우저 수동 검증(실제 펜/마우스로 그려보기, 타일 경계를 넘는 스트로크의 이음매, `E` 토글, 커서 크기)은 M2의 패닝/줌과 함께 다음 체크포인트에서 한 번에 진행한다 — 개발 서버 실행이 필요해 사용자에게 요청해 둔 상태다.
