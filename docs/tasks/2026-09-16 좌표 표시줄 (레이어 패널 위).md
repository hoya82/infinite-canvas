# 좌표 표시줄 (레이어 패널 위)

작성일: 2026-09-16
상태: 구현 완료, 자동 검증 + 브라우저 수동(Playwright/CDP) 검증 완료

## 요구사항

레이어 패널 위에 현재 뷰포트 좌표를 표시하고, 클립보드로 복사/붙여넣기할 수 있게 한다.

1. 좌표 = 현재 뷰포트 정중앙의 위치. 타일 단위 부동소수점, 소수점 둘째 자리까지 표시(예: (0,0)
   타일 정중앙을 보고 있으면 (0.5, 0.5)). 좌측/상단으로 이동하면 음수.
2. 줌 레벨도 함께 표시. (작업 도중 정수 → 소수점 첫째 자리, 0.1 단위로 변경됨. 아래 "후속
   수정" 참고.)
3. 표시 형식은 `x [ ] y [ ] 🔎[ ]`처럼 파싱된 개별 필드이고, 그 자리에서 직접 입력해 이동도
   가능하다.
4. 클립보드 복사 형식은 URL — `baseurl?x=17.54&y=-88.12&zoom=14` — 이고, 이 URL을 주소창에
   직접 입력해 열어도 그 위치로 점프해야 한다.
5. 클립보드에서 좌표 URL을 붙여넣는 용도로 작은 textarea를 별도로 둔다.

## 변경 사항

- **`src/lib/canvas/viewport.svelte.ts`**:
  - `Viewport`에 `centerWorld()`(화면 정중앙의 월드 좌표), `panCenterTo(worldX, worldY)`(줌은
    그대로 두고 정중앙만 이동), `jumpTo(worldX, worldY, zoom)`(줌을 clamp해 세팅한 뒤 정중앙
    이동) 세 메서드를 추가했다.
  - `activeViewport`(모듈 싱글턴이 아니라 `{ current: Viewport | null }` 형태의 홀더) 추가 —
    지금 마운트된 `CanvasStage`의 `Viewport` 인스턴스를 레이어 패널 위 컴포넌트 같은 형제
    컴포넌트에서도 읽을 수 있게 한다. 진짜 모듈 싱글턴으로 만들지 않은 이유: `CanvasStage`는
    도큐먼트를 전환할 때마다(`documentState.load()`가 `loading`을 토글해) 통째로
    언마운트/재마운트되고 그때마다 `Viewport`도 새로 만들어지는데, 이게 "새 도큐먼트를 열면
    뷰가 기본값으로 리셋되는" 기존 동작이다 — 싱글턴으로 바꾸면 이 리셋이 사라지는 회귀가
    생긴다. `CanvasStage.svelte`가 마운트 시 `activeViewport.current = viewport`,
    `onDestroy`에서 `null`로 해제하는 방식으로 기존 리셋 동작을 그대로 보존했다.
- **`src/lib/canvas/coordinateAddress.ts`(신규)** — "뷰포트 주소" 개념(`{ x, y, zoom }`, 타일
  단위 부동소수점 좌표 + 부동소수점 줌)과 그 변환 함수들.
  - `getViewportAddress(viewport)` / `jumpToAddress(viewport, address)` — 뷰포트 ↔ 주소 왕복.
  - `formatCoordinate`(소수점 2자리) / `formatZoom`(소수점 1자리) — 표시용 포맷터.
  - `buildAddressUrl(address, currentHref)` — 현재 URL의 origin+path에 `x/y/zoom` 세 쿼리만
    새로 얹어 `baseurl?x=..&y=..&zoom=..` 형식을 만든다(기존에 남아있던 다른 쿼리는 버림).
  - `parseAddressInput(text)` — 전체 URL이든, `?`로 시작하는 쿼리든, `?` 없는 쿼리든 모두
    받아들여 파싱한다. **버그를 하나 잡았다**: `URLSearchParams.get()`은 없는 키에 `null`을
    반환하는데 `Number(null) === 0`이라, 처음엔 `zoom` 파라미터가 아예 빠진 입력을
    "zoom=0"으로 잘못 파싱했다 — `has()`로 존재 여부를 먼저 확인하도록 고쳤다.
  - `consumeInitialUrlAddress(search)` — 페이지가 열릴 때 주소창 쿼리에서 좌표를 읽되, 앱
    세션당 딱 한 번만 반환한다(모듈 레벨 플래그). 도큐먼트를 전환해 `CanvasStage`가
    재마운트되어도 이 초기 주소가 되풀이 적용되지 않게 하기 위함 — "공유 링크로 열었을 때 한
    번" 점프하는 것이지 매 문서 전환마다 되풀이할 동작이 아니다.
- **`src/lib/components/CanvasStage.svelte`** — `Viewport` 생성 직후 `activeViewport.current`
  등록/`onDestroy` 해제. 최초 `resize()` 호출(→ `viewport.width/height` 확정) 바로 뒤에
  `consumeInitialUrlAddress(window.location.search)`를 확인해 있으면 `jumpToAddress`.
- **`src/lib/components/CoordinateBar.svelte`(신규)** — `x [ ] y [ ] 🔎[ ]` 세 필드 + 복사
  버튼 + 붙여넣기 textarea. 각 필드는 포커스 중엔 로컬 입력값을, 아닐 때는 `activeViewport`의
  실시간 값을 보여주는 controlled input이고, blur/Enter에서 커밋해 `jumpToAddress`를 호출한다.
  복사 버튼은 `navigator.clipboard.writeText`로 URL을 복사한다(권한 프롬프트 없음 — 쓰기는
  기본 허용). 붙여넣기는 별도 clipboard-read 권한이 필요 없도록, 사용자가 직접
  Ctrl+V하는 일반 `<textarea>`의 `oninput`에서 파싱해 성공하면 바로 이동하고 비운다.
- **`src/routes/+page.svelte` / `src/lib/components/LayerPanel.svelte`** — `LayerPanel` 위에
  `CoordinateBar`를 두는 `.sidebar` 래퍼 도입. 기존에 `LayerPanel` 자신이 갖고 있던
  `width:260px`/`border-left`를 래퍼로 옮기고, `LayerPanel`은 `flex:1`로 남은 세로 공간을
  채우게 했다.
- 테스트: `viewport.spec.ts`에 `centerWorld`/`panCenterTo`/`jumpTo` 3개 추가.
  `coordinateAddress.spec.ts`(신규) — (0,0) 타일 정중앙이 (0.5,0.5)가 되는지, 음수 좌표, 줌
  반올림, 왕복 변환, 포맷터, URL 빌드(기존 쿼리 제거 확인), 파싱(전체 URL/`?`쿼리/맨 쿼리/줌
  단위/누락 필드), 세션당 1회 소비. 전체 스위트 19개 파일 98개 테스트 통과, `svelte-check` 0
  에러, lint 통과.

## 후속 수정 — 줄 레벨을 정수에서 0.1 단위 부동소수점으로

구현 도중 사용자가 "줌 레벨이 좀 더 촘촘해야 할 것 같다"며 정수 대신 0.1 단위 부동소수점으로
바꾸자고 제안해 반영했다. `getViewportAddress`/`parseAddressInput`이 `Math.round(zoom)` 대신
`roundToTenth(zoom)`(10배 해서 정수로 반올림 후 다시 나누는 방식 — 부동소수점 오차가 더
적다)을 쓰도록 바꾸고, `formatZoom`을 `toFixed(1)`로, 줌 입력 필드의 `inputmode`도
`numeric`에서 `decimal`로 바꿨다. **"zoom"이라는 이름은 절대 "z"로 줄이지 말라는 사용자 지시가
있었다** — 이 프로젝트에서 `z`는 다른 의미와 충돌한다고 함. 관련 메모리에 기록해 둠.

## 검증

- **단위 테스트**: 위 "변경 사항" 참고. `parseAddressInput`의 "zoom 파라미터가 없으면
  `Number(null)===0` 때문에 zoom=0으로 잘못 파싱되는" 버그를 테스트로 직접 잡아냈다.
- **브라우저 검증**(WSL→Windows Chrome, CDP 연결, dev 서버는 사용자가 이미 띄워 둔
  `localhost:5173` 그대로 사용): Playwright로 실제 앱에서
  - 좌표 표시줄이 레이어 패널 바로 위에 정확히 자리잡은 것을 스크린샷으로 확인.
  - x 필드를 직접 편집(`10.25` 입력 후 Enter)하면 그 좌표로 실제로 점프하는 것을 확인.
  - "복사" 버튼을 누르면 클립보드에 `http://localhost:5173/?x=..&y=..&zoom=..` 형식의 URL이
    담기는 것을 `navigator.clipboard.readText()`로 직접 확인.
  - 그 형식의 URL을 붙여넣기 textarea에 넣으면(주소창에 입력하는 것과 동일한 파싱 경로) 즉시
    그 좌표/줌으로 점프하는 것을 확인.
  - **버그를 하나 더 발견**: 붙여넣기 성공 후 textarea가 시각적으로 비워지지 않는 문제 — 같은
    `input` 이벤트 핸들러 안에서 `pasteText`를 다시 `''`로 되돌리는 반응형 갱신을 브라우저가
    신뢰성 있게 반영하지 않았다. `oninput` 핸들러에서 `target.value = ''`로 DOM 값도 직접
    비우도록 고쳐 재검증했고, 정상적으로 비워짐을 확인했다.

## 후속 수정 — Ctrl+V가 스포이드 모드와 충돌하던 버그

배포 후 사용자가 "Ctrl+V가 스포이드 툴과 충돌하거나 입력 박스에 붙여넣기가 안 먹는다"고
보고했다. 원인은 `src/lib/canvas/input.ts`의 `ctrlHeld$()` — 바로 옆의 `spaceHeld$()`나
`toggleTool$`(E 키)는 전부 `isEditableTarget(e.target)`으로 입력 필드에 포커스가 있을 때를
걸러내는데, `ctrlHeld$()`만 그 필터가 없었다. 그래서 좌표 표시줄의 붙여넣기 textarea(이번
작업으로 새로 생김)나 다른 어떤 텍스트 입력에 포커스가 있는 상태에서 Ctrl+V/C/A/Z 등 Ctrl
조합 단축키를 누르면, 그 keydown 이벤트의 `e.ctrlKey === true`가 그대로 `baseMode$`를
`eyedropper`로 바꿔버려 캔버스 커서가 스포이드 아이콘으로 바뀌는 등 눈에 띄는 충돌이 있었다
(실제로 브라우저에서 재현해 확인함).

**수정**: `ctrlHeld$()`가 "눌림 시작"(`e.ctrlKey === true`)만 `isEditableTarget`으로 거르고,
"떼짐"(`e.ctrlKey === false`)은 절대 거르지 않도록 고쳤다 — `spaceHeld$()`의 `up$`가 대상
필터 없이 항상 통과시키는 것과 같은 이유로, 뗌 신호까지 거르면 입력 필드로 포커스가 옮겨간
채로 Ctrl을 놓을 때 눌림 상태가 고정돼버리는 새 버그가 생긴다. 겸사겸사 `spaceHeld$()`에 이미
있던 "창 포커스를 잃으면(Alt+Tab 등) 눌림 고정 방지" `blur$` 폴백도 `ctrlHeld$()`에 똑같이
추가했다(기존엔 없었음 — 같은 부류의 버그를 방지하는 일관된 패턴이라 함께 반영).

사용자가 함께 요청한 사항도 확인해 반영했다: "붙여넣은 URL의 baseurl이 이 앱의 것과 달라도
에러 없이 좌표 부분만 파싱해서 받아들일 것" — `parseAddressInput`은 애초에 origin/path를
검사하지 않고 `URLSearchParams`만 뽑아 쓰므로 이미 이 요구사항을 만족하고 있었고, 완전히 다른
호스트의 URL을 실제 Ctrl+V로 붙여넣어 정상 파싱/이동됨을 재검증했다.

**검증**: `src/lib/canvas/input.svelte.spec.ts`에 회귀 테스트 3개 추가 — 입력 필드 포커스 중
Ctrl 누름은 eyedropper로 안 바뀜, 입력 필드가 아닌 곳(캔버스 등)에서는 여전히 정상적으로
eyedropper로 바뀜(회귀 아님 확인), 입력 필드에 포커스가 있는 채로 Ctrl을 떼도 정상적으로
draw로 돌아옴(고정 안 됨). 브라우저(Playwright/CDP)에서도 실제 Ctrl 키다운 중 캔버스 커서를
`getComputedStyle`로 직접 확인해 재현/수정을 모두 확인했다. 전체 스위트 19개 파일 101개
테스트 통과.

## 후속 수정 — 입력/붙여넣기 즉시 이동을 "이동" 버튼 + Enter 커밋으로 변경

위 Ctrl+V 버그의 진짜 근본 원인은 사용자가 다시 짚어줬다: **입력하거나 붙여넣는 즉시
이동(jump)이 트리거되는 것 자체가 문제**였다 — eyedropper 커서 하이재킹은 그 위에 겹친
증상일 뿐, 값을 다듬을 새도 없이 한 글자 입력/붙여넣기마다 뷰포트가 움직여버리는 게 근본
불편함이었다.

**변경**: x/y/zoom 필드에 입력해도, 붙여넣기 textarea에 붙여넣어도 더는 즉시 이동하지 않는다.

- 좌표 필드 옆에 "이동" 버튼(`Navigation` 아이콘)을 추가했다. **Enter 키(세 필드 중 아무
  곳에서나, 또는 붙여넣기 textarea에서)나 이 버튼을 눌러야만** 그 순간 입력창에 있는 x/y/zoom
  값으로 실제 이동한다.
- 붙여넣기는 이제 URL을 파싱해 x/y/zoom 입력창에 값만 채워 넣고, 이동은 하지 않는다 — 붙여넣은
  값을 보고 사용자가 원하면 미세조정한 뒤 이동을 눌러도 되게 했다.
- 편집 중(아직 커밋 전)에는 입력값을 그대로 유지하고 실시간 값 갱신을 멈춘다
  (`isDirty` 플래그) — 그 사이 팬/줌을 해도 편집 중인 값이 덮어써지지 않는다. 이 상태에서
  "이동" 버튼이 파란색으로 강조되어 "적용 대기 중"임을 알린다. `Escape`를 누르면 편집을
  취소하고 실시간 값으로 되돌아간다.
- 유효하지 않은 값(숫자가 아님)으로 이동을 시도하면 입력을 조용히 지우지 않고 그 자리에 에러
  메시지를 보여준다 — 사용자가 뭘 잘못 입력했는지 보고 고칠 수 있게.

**검증**(브라우저, Playwright/CDP): x 필드에 타이핑만 해서는 이동하지 않음, Escape로 취소하면
실시간 값 복귀, x/y/zoom을 각각 편집한 뒤 Enter 한 번으로 세 값이 함께 커밋됨, "이동" 버튼
클릭으로도 동일하게 커밋됨, 숫자가 아닌 값 입력 시 에러 메시지 + 원래 입력 유지, 실제
Ctrl+V로 URL을 붙여넣으면 필드만 채워지고 즉시 이동하지 않다가 "이동"을 눌러야 커밋되고
그제서야 textarea가 비워짐 — 그리고 이 전체 과정에서 캔버스 커서가 eyedropper로 바뀌지
않음(이전 수정과 합쳐 재확인)까지 전부 확인했다. `svelte-check`/`eslint`/전체 테스트
101개 통과.

## 후속 수정 — 이동해도 캔버스가 즉시 다시 그려지지 않던 버그

사용자가 "점프를 했을 때 바로 반응하지 않고 캔버스에 특정 액션을 해야 캔버스가 업데이트된다"고
보고했다. 원인: `CanvasStage.svelte`의 렌더링은 전부 명령형이다 — `scheduleRender()`를
호출해야만 다음 애니메이션 프레임에 `doRender()`가 실제로 그린다. 기존의 모든 뷰포트 변경
경로(팬 드래그, 줌 드래그, 휠 줌, 리사이즈)는 `viewport`를 바꾼 직후 각자 직접
`scheduleRender()`를 호출하는 식으로 되어 있었는데, **이 컴포넌트 바깥(좌표 표시줄)에서
`jumpToAddress`로 `viewport.panX/panY/zoom`을 직접 mutate하는 새 경로에는 그 호출이
없었다** — `viewport`가 `$state`라 값 자체는 바뀌지만, `doRender()`는 그 값을 구독하는
반응형 코드가 아니라 그냥 한 번 실행되고 끝나는 명령형 함수라 아무도 다시 그려야 한다는 신호를
주지 않으면 화면은 그대로 남는다. 그러다 사용자가 캔버스 위에서 마우스를 움직이거나 팬/줌을
하면 "그 액션 자체의" `scheduleRender()` 호출이 우연히 최신 `viewport` 값으로 그려주니까
그제서야 반영된 것처럼 보였던 것이다. (덤으로: 페이지를 열 때 주소창 쿼리로 점프하는 초기
경로도 같은 구멍이 있었는데, 그 직후 `resize()`/`refreshExistingTiles()`가 어차피
`scheduleRender()`를 부르는 경우가 많아 우연히 가려져 있었을 뿐이었다.)

**수정**: 특정 호출 경로 하나를 패치하는 대신, 렌더링 자체를 `viewport`의 상태에 반응하게
만들었다 — `CanvasStage.svelte`에 `viewport.panX/panY/zoom/width/height`를 읽고
`scheduleRender()`를 호출하는 `$effect`를 추가했다. 이러면 **누가 어디서 viewport를
바꾸든**(내부 팬/줌 핸들러든, 좌표 표시줄의 "이동"이든, 앞으로 추가될 어떤 기능이든) 항상
다시 그려지므로, 이 종류의 버그가 다시 생길 여지를 원천적으로 없앤다. 기존 핸들러들의 수동
`scheduleRender()` 호출은 그대로 남겨뒀다 — `scheduleRender()`가 이미 `rafHandle` 가드로
중복 호출을 무시하므로 두 경로가 겹쳐도 무해하고, 손댈 필요가 없는 코드를 건드리지 않는 쪽을
택했다.

**검증**(브라우저, Playwright/CDP): `CanvasRenderingContext2D.prototype.clearRect`(렌더러가
매 프레임 무조건 호출하는 함수)를 페이지 로드 전에 패치해 호출 횟수를 셌다 — 좌표 필드에
값을 입력하고 Enter만 눌렀을 때(캔버스에 마우스를 올리거나 어떤 액션도 하지 않음)
`clearRect` 호출 횟수가 2 → 3으로 늘어 실제로 다시 그려졌음을 확인했다. 전체 테스트 101개,
`svelte-check`, `eslint` 모두 통과.

## 알려진 한계 (의도적으로 남겨둠)

- 뷰포트 위치/줌은 어디에도 영속화되지 않는다(기존부터 그랬음) — 페이지를 새로고침하면 주소창에
  쿼리가 없는 한 기본 위치로 돌아간다. 이번 작업은 "명시적으로 좌표를 공유/복귀하는 기능"을
  추가한 것이지, 뷰 상태 자동 저장을 추가한 것은 아니다.
- 도큐먼트를 전환하면(사이드바의 문서 전환) 뷰포트가 기본값으로 리셋되는 기존 동작을 그대로
  유지했다 — 좌표 표시줄도 그 리셋된 값을 그대로 보여준다.
- 초기 주소창 쿼리 소비는 앱 세션(탭)당 1회로 제한했다 — 여러 문서를 오가는 동안 계속 같은
  주소를 재적용하지 않기 위함이며, 의도한 설계다.
